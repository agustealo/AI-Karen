# 01 | Mission, scope and terminology

[← Index](README.md) · [Next: Repository audit →](02-repository-audit.md)

## 1. What KCM is

**Karen Consciousness-Model (KCM)** is the product label for Karen's **operational self-model**: an auditable representation of her configured identity, current skills, demonstrated task capabilities, lessons from past outcomes, knowledge boundaries and uncertainty. It can draw on memory and evaluation evidence. It must not represent unverifiable internal experience as literal sentience or human consciousness.

**KCM is not identical to LNTG.** LNTG, if retained as a name, describes a lightweight neural text-generation capability, one *possible consumer* of approved training datasets. KCM is a higher-level, primarily data- and evidence-driven self-description. They must not become two new orchestrators.

## 2. Objectives

- Preserve consistency across models/providers and over time without making any model the source of truth for identity or knowledge.
- Learn demonstrable procedural skills from validated successes and corrected failures.
- Express capability and uncertainty accurately: know what has been tested, under what conditions, and when to defer.
- Admit **high-learning-value, policy-allowed** examples into versioned datasets; avoid training on raw memories by default.
- Preserve current CORTEX policy decisions, ChatRuntime execution, memory governance, plugin permissions and model choice contracts.
- Make adaptation local-first, measurable, reversible and independently auditable.

## 3. Non-goals

- Claiming phenomenal consciousness, feelings, self-directed personhood or agency.
- Replacing CORTEX, RuntimePolicy, NeuroRecall, NeuroVault, provider routing, or general LLM capability.
- Encoding user secrets/personal facts as model weights.
- Building a second STM/LTM system or duplicating memory retention logic.
- Automatically retraining from every conversation, recall hit or LTM promotion.
- Expanding permissions on the basis of self-assessed skill.
- Treating a self-generated completion, synthetic teacher output or usage frequency as independent ground truth.

## 4. Vocabulary (do not conflate)

| Term | Definition | Canonical authority |
|---|---|---|
| Memory worthiness | Should an observation be retained? | `core/memory/formation` and memory policy |
| Recall ranking | Which permitted memories are relevant now? | NeuroRecall |
| Knowledge validity | Is a claim supported, current and appropriately scoped? | Existing belief/claims/evidence contracts and authoritative provenance |
| Training candidate | Source potentially useful to a declared training objective | EchoCore |
| Training admission | Authorization + suitability of a candidate for an objective | EchoCore training-admission policy |
| Dataset membership | Selection in a particular immutable, versioned training set | Existing learning dataset owner, extended |
| Model adaptation | Changing trainable model/adapter parameters | Existing training/model lifecycle owners |
| Capability evidence | Measured outcomes proving or limiting a task skill | Existing outcome/evaluation contracts |
| KCM snapshot | Derived view of identity, lessons, capabilities and uncertainties | Existing cognitive/user-state/evidence projections; no second durable truth |
| Retrieval success | A memory was used in context | **Not** proof of task correctness |
| Training quality | Utility for a specified model and objective | Independent evaluation, not memory `importance` |

## 5. Three distinct loops

1. **Working/episodic loop:** record observations, user instructions and execution outcomes; governed memory formation.
2. **Self-model loop:** project evidence of task performance, learned procedures, capability estimates and unknowns; no neural fine-tuning required.
3. **Parametric learning loop:** screen and curate candidate examples; evaluate potential model/adapter improvement; train offline; promote only after certification.

The first two should work independently of whether a neural model is ever trained. The third is optional and strictly gated.

## 6. Explicit noninterference rule

KCM can provide advisory skill and uncertainty evidence to CORTEX. CORTEX determines cognitive task suitability, RuntimePolicy determines authorization, ChatRuntime executes. A KCM self-report is never a permission grant, credential, or substitute for verified tool/model readiness.

## 7. Adoption success

Success means that Karen makes measurably better, better-calibrated decisions about her own capability and produces improved outcomes on certified tasks, **without** crossing tenant boundaries, weakening policy, or increasing global regressions. A beautiful Persona response alone is not success.
